# 08 — החלטות פתוחות

כל החלטה: מה השאלה, האפשרויות, יתרונות וחסרונות. אין המלצה — ההחלטה של עידן.
אחרי החלטה: לעדכן כאן עם תאריך ולהעביר ל-`CLAUDE.md`.

## D1 — טכנולוגיית UI

| אפשרות | יתרונות | חסרונות |
|---|---|---|
| Jetpack Compose + M3 | רכיבי M3 Expressive חדשים מגיעים קודם לכאן; פחות קוד; RTL אוטומטי | רשימות ענק (אלפי פריטים) דורשות כיוונון ביצועים |
| Views + MDC | בשל מאוד לרשימות גדולות (RecyclerView) | קוד רב יותר; פיצ'רי Expressive מגיעים מאוחר או לא מגיעים |

## D2 — מודל גישה לקבצים

| אפשרות | יתרונות | חסרונות |
|---|---|---|
| All files access | חוויית “מנהל קבצים אמיתי”; מהיר (java.io) | הצהרה ב-Play; לא נותן Android/data |
| SAF בלבד | אין הרשאות רגישות | איטי מאוד; חוויית בחירת תיקיות מסורבלת |
| All files + Shizuku | פותח גם Android/data (כמו Solid; Shizuku כבר מותקן אצל עידן) | תלות בשירות חיצוני שצריך לרוץ |
| + root | גישה מלאה | לא רלוונטי למכשיר לא מרוטט |

## D3 — היקף פרוטוקולי רשת בגרסה הראשונה

| אפשרות | יתרונות | חסרונות |
|---|---|---|
| SMB בלבד | מכסה את ה-NAS; ספרייה אחת | אין גישה ל-Pi ב-SFTP |
| SMB + SFTP + WebDAV | NAS + Pi + Nextcloud/שרתים אחרים | 3 מימושים לתחזק |
| כל מה שב-Solid (כולל FTP/FTPS/S3/NFS) | שוויון יכולות | היקף בדיקות גדול; חלק נמוך שימוש |

## D4 — ענן

| אפשרות | יתרונות | חסרונות |
|---|---|---|
| בלי ענן בהתחלה | אין OAuth/אימות אפליקציה מול ספקים | פער מול Solid |
| Google Drive בלבד | שירות אחד מוכר | דורש פרויקט Google Cloud + מסך הסכמה |
| מספר שירותים | שוויון | כל ספק — SDK, מגבלות קצב ותחזוקה משלו |

## D5 — הפצה ועדכונים

| אפשרות | יתרונות | חסרונות |
|---|---|---|
| Google Play | עדכונים אוטומטיים, Billing | הצהרת All files access, סקירה, חשבון מפתח |
| עדכון עצמי (כמו TiviCopy — updates.idanck.com) | תשתית קיימת; בלי מגבלות מדיניות Play | רק לשימוש פרטי; ניהול keystore נוסף |
| שניהם | גמישות | שתי שרשראות build |

## D6 — מונטיזציה

| אפשרות | יתרונות | חסרונות |
|---|---|---|
| אין (שימוש אישי) | ממשק נקי, בלי SDK פרסום | אין הכנסה |
| Freemium כמו Solid | הכנסה אפשרית | ניהול רישוי, פרטיות, עסק רשום |
| תשלום חד-פעמי | פשוט | ניהול רישוי + הפצה ב-Play |

## D7 — מדיניות RTL

| אפשרות | יתרונות | חסרונות |
|---|---|---|
| שיקוף מלא לפי locale | עקבי בעברית; סוגר את פערי Solid (05) | שמות קבצים באנגלית מיושרים לימין — דורש טיפול BiDi בכל שורה |
| ממשק LTR תמיד, טקסט בעברית | פשוט; נתיבים ושמות אנגליים קריאים | לא עקבי עם שאר המערכת |

## D8 — זהות חזותית

| אפשרות | יתרונות | חסרונות |
|---|---|---|
| שיכפול קרוב של Solid | מוכר לעידן | שימוש במותג ובנכסים של NeatBytes אסור בהפצה ציבורית |
| אותם עקרונות M3 Expressive, צבעים/לוגו משלך | עצמאי; אפשר להוציא מערכת עיצוב מסודרת | עבודת עיצוב נוספת |
| Dynamic color בלבד | אפס עבודת צבע | אין זהות; מראה שונה בכל מכשיר |

## D9 — minSdk

| אפשרות | יתרונות | חסרונות |
|---|---|---|
| 26 (Android 8) | כיסוי רחב | הסתעפויות הרשאות לפני/אחרי Android 11 |
| 30 (Android 11) | מודל הרשאות אחד (All files access) | משמיט מכשירים ישנים |
| 31 (Android 12) | Dynamic color תמיד זמין | משמיט יותר |

## D10 — שם

`nexplorer` הוא שם עבודה שנבחר לריפו בלבד. שינוי שם ריפו בגיטהאב משאיר redirect; applicationId קשה לשנות אחרי הפצה — לקבוע לפני build ראשון.
