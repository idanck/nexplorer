# תוכנית מימוש — שלב 7: Synology

> 30/10/2026. ממשיך את [`06-phase6.md`](06-phase6.md). **אושר על ידי עידן (30/10/2026)** — לוח [Synology](../design/screens/Synology.webp) (`boards/Synology.dc.html`). D2, ‏D6 ו-D10 נשארים פתוחים, ושום דבר כאן לא תלוי בהם.

## מטרה

NAS של Synology כמקום במגירה — לא דרך SMB אלא דרך ה-API של DSM (File Station). שני סוגי חיבור, באותו אריח "Synology":

| חיבור | כתובת | מתי עובד |
|---|---|---|
| **רשת ביתית** | שרת ופורט של DSM (‏HTTPS) | בבית, או מבחוץ דרך VPN. לא צריך פורט פתוח בראוטר |
| **QuickConnect** | מזהה QuickConnect | בכל מקום: בבית — ישירות לכתובת המקומית של ה-NAS; בחוץ — דרך ממסר של Synology |

אחרי ההתחברות — אותו מסך קבצים, אותו תור העברות ואותם תפריטים. מה שמצדיק API ולא SMB: **תמונות ממוזערות, חיפוש עמוק בשרת, והעתקה/העברה בתוך ה-NAS בלי לעבור דרך הטלפון.**

## מה נכנס

| תחום | מה | API |
|---|---|---|
| הוסף מקום | אריח "Synology" (בשורה הראשונה, אחרי WebDAV). בחירה "רשת ביתית" / "QuickConnect". רשת ביתית: שרת, פורט (ברירת מחדל 5001), משתמש, סיסמה; DSM שנמצא ברשת (mDNS) — "בחר". ‏QuickConnect: מזהה, משתמש, סיסמה; בבדיקה — "המזהה נמצא", "מחובר דרך: מקומי / ממסר" | `SYNO.API.Auth` |
| אימות דו-שלבי | חשבון עם קוד — שדה "קוד אימות" אחרי הניסיון הראשון; המכשיר נשמר כמהימן (device token) כדי שלא ייבקש בכל פעם | `SYNO.API.Auth` (‏`otp_code`, ‏`enable_device_token`) — **ייבדק במימוש** |
| דפדוף | בשורש — השיתופים שהמשתמש רואה; אחר כך תיקיות, בדפים של 1,000. מקום פנוי מהשיתוף. 4 מצבי תצוגה, מיון, סינון, מועדפים, "רק בתיקייה זו" | `List.list_share`, ‏`List.list`, ‏`List.getinfo` |
| תמונות ממוזערות | תמונה ווידאו — תמונה קטנה מה-NAS (‏small ברשימה, ‏medium ברשת), במטמון בזיכרון ובדיסק. וידאו — עם ▶ | `Thumb.get` |
| פתיחה וניגון ישיר | שמע, וידאו ואפליקציה אחרת קוראים ישירות מה-NAS, עם דילוג (`Range` — ‏206) | `Download.download` |
| העלאה | multipart, בלי דריסה, עם תאריך השינוי של המקור | `Upload.upload` |
| בשרת | תיקייה חדשה, שינוי שם, מחיקה (תיקייה — רק ריקה, כמו בכל מקום), מאפיינים, "גודל תיקיות" | `CreateFolder`, ‏`Rename`, ‏`Delete`, ‏`DirSize` |
| העתקה והעברה בתוך ה-NAS | בצד השרת — ממשימה בתור ההעברות, עם התקדמות ועצירה. בין NAS למכשיר — דרך הטלפון, כמו היום | `CopyMove` |
| חיפוש עמוק | מסך החיפוש הרגיל (מסננים ותחביר) — ה-NAS מחפש בבקשה אחת, התוצאות זורמות, "עצור". "בתיקייה הנוכחית" / "בכל השיתוף" | `Search` (‏start/list/stop/clean) |

## מה לא

- **Synology Photos, ‏Drive, ‏Download Station, קישורי שיתוף, שחזור מסל המחזור, ניהול DSM.**
- **פריצת NAT ישירה ב-QuickConnect** (‏hole punching): מחוץ לבית — רק ממסר.
- **ארכיונים והצפנה בתוך ה-NAS:** כמו בשאר הרשת — דרך עותק במכשיר.
- **SMB לאותו NAS לא מוחלף:** החיבור הקיים נשאר; אפשר את שניהם.

## החלטות מימוש (לא החלטות מוצר)

| נושא | בחירה | למה |
|---|---|---|
| נתיב | `syno://<חיבור>/<שיתוף>/<תיקייה>/...` — הנתיב של File Station אחרי המזהה | מועדפים, תצוגות ותיקיות מוסתרות עובדים בלי שינוי |
| סוג החיבור | `NetProtocol.Synology` אחד; ל-QuickConnect — שדה מזהה בחיבור (בלי שרת) | אותו `SynologyFs` לשניהם; רק הכתובת נקבעת אחרת |
| HTTP | OkHttp, כמו בענן. `_sid` בכל בקשה; כשל 106/107/119 (פג/נותק) — התחברות מחדש פעם אחת וניסיון חוזר | ה-sid פג אחרי זמן |
| תעודה ברשת הביתית | בחיבור הראשון — טביעת האצבע של התעודה (SHA-256) להצגה ואישור, ואז נשמרת ונבדקת בכל חיבור — כמו מפתח השרת ב-SFTP. תעודה תקפה לשם — בלי שאלה | ברשת ניגשים בכתובת IP, ו-DSM מגיש תעודה על שם אחר או חתומה עצמית |
| QuickConnect — בחירת כתובת | `get_server_info`; ניסיון מקביל (2 שניות) לכתובות המקומיות, ואחר כך הממסר. נבחרת הראשונה שעונה ל-`SYNO.API.Info`. נבדק שוב כשהרשת משתנה | בבית — מהירות מלאה |
| QuickConnect — סיכון | הפרוטוקול של `Serv.php` לא מתועד רשמית. שינוי אצל Synology — הודעה "QuickConnect לא זמין — השתמש ברשת ביתית" | אין חלופה רשמית |
| העתקה בתוך ה-NAS | אותו חיבור, שני נתיבים ב-`syno://` — `CopyMove` בשרת; אחרת — דרך הטלפון | חוסך את ההורדה וההעלאה |
| חיפוש | `SearchViewModel` מקבל מקור: מקומי (סריקה) או שרת (`Search`). המסננים — לפרמטרים של `Search` (‏`pattern`, ‏`extension`, ‏`size_from/to`, ‏`mtime_from/to`); מה שאין לו פרמטר (שלילה ב-`!` ו"או") — סינון על התוצאות בטלפון | אותו מסך |
| שגיאות | `SynoErrors` ← עברית (400 "שם משתמש או סיסמה שגויים", 403 "צריך קוד אימות", 407 "החשבון חסום זמנית", 408/409 "אין הרשאה" וכו') | — |

## בטיחות

- משתמש DSM ייעודי בלי הרשאות ניהול, עם גישה רק לשיתופים הנחוצים. הסיסמה ב-Android Keystore, כמו בשאר החיבורים.
- "רשת ביתית" לא דורש שום פתח בראוטר; מומלץ להגביל בחומת האש של DSM את פורט הניהול לרשת הביתית ולרשת ה-VPN.
- QuickConnect, כשהוא פעיל ב-DSM, חושף את מסך ההתחברות של DSM דרך הממסר של Synology לכל מי שיודע את המזהה — זה נכון בלי קשר לאפליקציה. משתמש בלי הרשאות ניהול וסיסמה חזקה מצמצמים את הנזק.
- שום פרט של NAS אמיתי (כתובת, מזהה QuickConnect, משתמש) לא נכנס לריפו; בדיקות מול NAS אמיתי רצות רק בסביבת הפיתוח, עם פרטים ממשתני סביבה.

## מצב

- **7א — מומש (30/10/2026):** `data/net/SynologyFs` (OkHttp), ‏`PinnedTls` (משותף עם WebDAV), ‏`RemoteThumb` (‏Coil, מטמון בזיכרון ובדיסק), ‏`syno-server.py`, ‏`SynologyFsTest`, ‏`Phase7Test`. שני דברים שונים מהטבלה למעלה:
  - **אימות דו-שלבי:** לא מומש — אין לו בדיקה בלי חשבון עם קוד. חשבון כזה מקבל הודעה ברורה ("בגרסה הזו אפשר להתחבר רק עם חשבון בלי קוד אימות"). ייכנס אחרי בדיקה מול NAS אמיתי.
  - **תמונות ממוזערות:** בתצוגת רשת וגלריה (medium) — כמו בקבצים במכשיר, שבתצוגת רשימה מוצגים באייקון.
  - נמצא מול NAS אמיתי: הורדה של קובץ שלא קיים עונה 502 בדף HTML, ותמונה ממוזערת שאין — 404 ב-HTML (לא JSON). השרת המדומה עונה כך גם.
